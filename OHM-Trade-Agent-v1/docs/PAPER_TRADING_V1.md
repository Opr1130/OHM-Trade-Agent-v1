# OHM Paper Trade v1 — Isolated Architecture

## Purpose

Paper Trade v1 validates whether OHM's final qualified advisory opportunities
produce profitable trade lifecycles without granting any additional exchange
authority.

This subsystem is deliberately isolated from production execution and account
state. It is not a Kraken dry-run order client and it never writes to Kraken.

## Authority boundary

Paper modules may read:

- final already-qualified OHM opportunity metadata;
- immutable O'Pip canonical episode/cohort identity;
- decision-time prices already present in the production scan;
- Kraken **public** OHLC/ticker data for later paper monitoring.

Paper modules must not import or mutate:

- Kraken private API clients;
- active-trade registry;
- pending-setup registry;
- order-intent registry;
- trade confirmation/registration paths;
- Telegram execution/lifecycle callbacks.

Static tests enforce this boundary.

## Operator control

Runtime control is a dedicated atomic registry and defaults to OFF.

Inside the application container:

    python -m app.services.paper_trade_cli on
    python -m app.services.paper_trade_cli off
    python -m app.services.paper_trade_cli status

Changing paper mode requires no .env edit and no container rebuild.

### OFF semantics

OFF prevents new paper exposure.

On the next monitor pass:

- unfilled paper entries are cancelled;
- already-open paper positions continue to a terminal outcome.

A missing or unreadable control file is not treated as an explicit operator
OFF. Existing pending entries freeze in place until control state is readable
again, while already-open paper positions continue to be monitored. This
prevents ambiguous control state from creating or deleting simulated exposure.

This prevents new simulated risk while avoiding survivorship/censoring bias in
positions that were already opened.

## Supported strategy scope

Paper Trade v1 is intentionally:

- Kraken spot;
- LONG only;
- one non-terminal paper lifecycle per symbol;
- bounded by paper-only capital and position capacity;
- independent from the user's real account balances.

SHORT/margin signals are recorded as unsupported by the enrollment result and
are not simulated in v1.

## Signal linkage

Every enrolled paper lifecycle stores:

- canonical cohort_id;
- canonical episode_id;
- symbol/base asset;
- decision timestamp;
- final rank and confidence;
- entry/stop/target geometry.

The episode id is generated by the same pure identity function used by the
post-alert O'Pip canonical producer, so paper outcomes can be joined back to the
exact decision-time episode.

## Entry model

### ENTER NOW

Uses the already-fetched decision-time ask when available, otherwise the
decision-time reference price.

Simulated market fill:

    ask/reference + configured slippage

The fill is rejected if it is beyond the approved chase boundary.

### PLACE LIMIT / pullback

Creates a paper pending entry at the approved long pullback limit.

No fill is invented at signal time.

## Monitoring model

Paper monitoring runs only after real active-position and pending-setup
protection have completed in the unified cycle.

It uses Kraken public OHLC data only.

The candle containing the original signal is excluded from high/low outcome
attribution because part of that candle occurred before the decision.

Only fully closed post-signal candles are evaluated.

The candle interval is frozen into each paper lifecycle at enrollment. Later
runtime configuration changes cannot change the historical sampling interval
of an already-open or pending paper trade.

Before advancing a lifecycle, the monitor verifies continuity from the next
required candle. A provable skipped historical interval terminates that
lifecycle as UNRESOLVED rather than allowing the simulator to skip unknown
price action. UNRESOLVED outcomes are excluded from realized P/L statistics. Their paper
capital remains quarantined rather than being released for reuse, because the
true terminal cash value is unknown. A temporary absence of a newly closed
candle simply freezes progress and is not counted as a loss or win.

## Conservative intrabar rules

OHLC cannot prove event ordering inside a candle. Therefore:

1. If stop and target are both touched in one candle, stop wins.
2. If a pending limit entry and stop are touched in the entry candle, the
   paper trade is filled and stopped.
3. Targets are never credited in the same candle that first fills a pending
   limit entry.
4. Market exits apply configured adverse slippage.
5. Target exits use the target limit price and still pay configured fees.

These rules intentionally bias against flattering paper performance.

## Profit-taking model

Paper Trade v1 supports:

- partial TP1 using configured fraction (default 50%);
- remaining quantity at TP2;
- original stop remains unchanged after TP1;
- no automatic break-even stop is invented;
- configured time exit for positions that remain open.

Fees are charged at entry and every realized exit leg.

## Capital model

Paper capital is isolated from the real account.

The paper account tracks:

- configured starting equity;
- realized closed-trade P/L;
- reserved capital for pending/open paper lifecycles;
- available paper capital;
- max simultaneous paper lifecycles.

Unrealized paper P/L does not increase available capital.

## Failure behavior

Paper trading is lower priority than production.

- control corruption prevents new paper exposure and freezes pending entries;
- one paper market-data failure does not stop other paper lifecycles;
- paper monitor failure cannot stop real active-position monitoring;
- paper enrollment occurs only after Telegram processing;
- paper persistence failure cannot change live ranking or trade authority;
- missing historical OHLC cannot be silently skipped into a paper win/loss.

## Known v1 limitations

Paper Trade v1 does not yet model:

- exchange queue position;
- partial limit-order fills;
- order-book depth/market impact;
- exact sub-candle path;
- short/margin financing;
- dynamic fee tier changes;
- manual operator latency;
- real execution acknowledgements.

These limitations must be considered when comparing paper P/L with future real
fills.

## Promotion rule

Paper results are evidence only. They do not automatically alter production
thresholds, strategy parameters, ranking, sizing, or execution authority.

Any future strategy change still requires O'Pip hypothesis/experiment
governance and explicit promotion.
